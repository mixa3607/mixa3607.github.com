# OpenBMC для RD450X

Порт апстримного [OpenBMC](https://github.com/openbmc/openbmc) на BMC этой платы (`AST2400`, флеш 32 МБ, 256 МБ RAM). Полностью заменяет стоковый AMI MegaRAC.

- Исходники (слой `meta-lenovo/meta-rd450x`): [github.com/delarun/rd450x-openbmc](https://github.com/delarun/rd450x-openbmc)
- Готовые образы: [releases](https://github.com/delarun/rd450x-openbmc/releases)

:::warning
Всё проверено на одной плате. Перед прошивкой снимите дамп стокового BMC и прочитайте раздел про восстановление.
:::

```yaml
Machine: rd450x
OpenBMC: 14d5a4165f04dd7606fb28585a315dbcf81a3dbc
Linux version: 6.18
```

## Особенности платы

То, что пришлось выяснять реверсом стока и на живой плате:

- Intel ME сидит на I2C шине 4 по адресу `0x16` и это единственный источник температуры CPU: команда Node Manager `0x4B` отдаёт запас до Tjmax по каждому процессору.
- Датчик температуры на плате - чип класса ADM1032 по адресу `0x4c` на шине 0.
- У `SYS_FAN1` нет сигнала тахометра, его PWM всегда 100%.
- UART1/UART2 (COM1/COM2 хоста) надо включать в device tree, иначе у них выключен клок и последовательные порты хоста мертвы.
- Блоки питания подключены не к BMC, а к ME (PMBus `0x58`/`0x59`). С обычным ATX блоком ME на запросы отвечает отказом.
- Разметка флеша отличается от стандартной для 32 МБ в OpenBMC (ядро 4.5 МБ, rofs 25 МБ, rwfs 2 МБ), иначе не влезает KVM.

## Прошивка и восстановление

UART-рекавери на `AST2400` нет. Рабочие варианты:

- **Первая прошивка и восстановление - из ОС хоста.** P2A мост VGA на этой плате открыт, поэтому [ASPEED iRMP SOC Flash](/docs/wiki/hardware/tools/ASPEED-iRMP-SOC-Flash-Utility/index.mdx) читает и пишет флеш BMC из линукса на хосте, даже если BMC мёртв:

  ```shell
  ./socflash_x64 -b stock-backup.bin
  ./socflash_x64 if=rd450x-openbmc-full-32M.static.mtd option=f
  ```

  Пока BMC в непонятном состоянии, хост не перезагружать и не выключать: `socflash` работает только из загруженной ОС.

- **Обновление по сети.** Скопировать `image-kernel` и `image-rofs` в `/run/initramfs/` на BMC и перезагрузить BMC. U-Boot и настройки сохраняются.

После полной прошивки окружение U-Boot пустое, MAC будет случайным. Вернуть свои (с наклеек на плате):

```shell
fw_setenv ethaddr XX:XX:XX:XX:XX:XX
fw_setenv eth1addr XX:XX:XX:XX:XX:XX
```

```yaml title="Creds"
login: root
passwd: 0penBmc
```

## Прошивка BIOS

Флеш BIOS (16 МБ) висит за мультиплексором на `GPIOH6`. BMC забирает его только при выключенном хосте.

```shell
rd450x-bios info                 # чип и регионы дескриптора
rd450x-bios backup /tmp/full.bin # весь флеш, включая регион ME
rd450x-bios write  /tmp/new.rom  # записать регион BIOS, около 2 минут
```

- Пишется только регион BIOS (`0x400000-0xffffff`). Дескриптор и регион ME не трогаются, образ с другим дескриптором отклоняется.
- Вместе с BIOS перезаписывается NVRAM: настройки и загрузочные записи UEFI берутся из образа.
- Из web ui: Operations → Firmware, обычный ROM на 16 МБ без упаковки. Хост должен быть выключен.
- Проверено на [rd450drx_NC.rom](/docs/wiki/hardware/intel_2011v3/Lenovo_RD450X/bios/rd450drx/index.md): чтение, запись и откат на свой дамп.

## BIOS rd450drx и IPMI

BIOS [rd450drx](/docs/wiki/hardware/intel_2011v3/Lenovo_RD450X/bios/rd450drx/index.md) собран из Supermicro X10DRX и разговаривает с BMC на диалекте Supermicro (NetFn `0x30`). Стоковый AMI понимает те же номера команд по-своему - вероятно, отсюда предупреждение автора не трогать настройки IPMI в Setup.

Под OpenBMC это выглядит так:

- Незнакомые команды `0x30` просто отклоняются, в BMC ничего не пишется.
- Реализована выгрузка файлов из BIOS (команда `0xA0`): BIOS сам отдаёт таблицы SMBIOS, из них строится инвентарь процессоров и памяти.
- Таблицы BIOS шлёт только при включённом **CSM Support** в Setup: модуль ищет их в сегменте `F000`, а без CSM их там нет. Загрузка через UEFI при этом продолжает работать.
- Первая выгрузка добавляет к загрузке около 35 секунд.
- Вкладка IPMI в Setup показывает рабочий BMC и его сетевые настройки.
- `Update IPMI LAN Configuration` лучше оставить в `No`: при `Yes` BIOS перепишет сеть BMC значениями из Setup.

Для другого BIOS или без CSM инвентарь можно отправлять из ОС хоста скриптом `host-tools/rd450x-smbios-push` (локальный IPMI, без сети и пароля BMC).
